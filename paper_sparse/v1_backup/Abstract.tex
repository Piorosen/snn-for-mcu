Spiking neural networks (SNNs) exchange binary spikes, yet integer SNN kernels on microcontrollers still execute dense multiply--accumulate (MAC) loops in which, at measured firing rates of 4--48\%, most products are multiplications by zero. Building on our prior fused Conv-AvgPool-LIF operator integrated into TensorFlow Lite for Microcontrollers (TFLM) with CMSIS-NN (2,407ms per CIFAR-10 image at $T{=}30$ on an STM32F746, 200MHz), we first re-diagnose the remaining bottleneck with cycle-accurate on-board measurements: enabling the ART accelerator and moving hot kernels to ITCM-RAM each yield no measurable gain ($\le$0.12\%, within noise) because code executes over the AXIM path and the inner loops fit the 4KB I-cache---the bottleneck is data loads, not instruction fetch. We then present a multiplication-free sparse kernel that exploits the binary $\{0, S\}$ activations: per output pixel it builds a nonzero-input index list directly from the receptive field (eliminating im2col materialization entirely), accumulates transposed weights ($[k][C_o]$ layout, 8-channel register blocking with paired loads and SXTAH) in int32, and applies $S$ once before the shared requantize-and-LIF epilogue, making the result bit-exact with the dense path by construction. Combined with DTCM/SRAM weight and state placement, latency drops from a reproduced 2,328.5ms baseline to 380.6ms per image (6.12$\times$; conv2 alone 13.8$\times$), with identical output-spike checksums across all six build variants, including both the TFLM (2.1\% overhead) and runtime-free paths. The five-step kernel iteration history, including one measured regression and its cause, is reported to document how each micro-architectural decision was validated on silicon.
